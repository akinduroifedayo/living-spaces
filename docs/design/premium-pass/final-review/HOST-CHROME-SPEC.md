## 1. Space header metadata

Rule: show only facts we have. Never render "Not reported", "Unknown", "N/A" or "—" for missing freshness/source data. A missing fact is omitted, not described.

Code: `absolute(null)` returns '' (not 'Not reported'). `<Time at={null}>` renders null. Callers guard. Remove all 'Not reported' strings listed above.

Meta line (12px, secondary), segments joined by " · ", owner chip first:
| Data | Line |
|---|---|
| last_success known, source_as_of known and differs >=60 s from last_success | `{Owner} · Updated {rel} · Source data from {rel}` |
| last_success known, source missing or within 60 s | `{Owner} · Updated {rel}` |
| no success, last attempt ok-pending/never | `{Owner} · Not refreshed yet` |
| no success, last attempt failed | `{Owner} · No successful update yet` |
| building | `{Owner} · Building the first version` |
| archived | `{Owner} · Archived {rel}` |
`{rel}` = relative ("12 min ago", "Yesterday, 6:00 AM" after 24 h); every segment is a `<time datetime>` with `title` = absolute with zone ("Nov 11, 2:05 AM CST"). Re-render on the existing 2 s detail poll. Status pill unchanged ("Ready").

Source data is never inferred. If a feed doesn't report it, the segment is absent. No tooltip explaining absence.

Idle save status: remove "No unsaved changes". Keep `.ls-save` mounted as an empty role=status live region; render text only for Saving…, Saved {time}, and the failure states (copy unchanged).

Header action cluster (replaces the current one):
`[Upkeep: {state}] [History] [Permissions] [Refresh now (primary)] [⋯]`
- Upkeep button labels: no job `Upkeep: none` · on `Upkeep: on` · paused `Upkeep: paused` · job missing `Upkeep: job missing`. Opens the Upkeep drawer. (Replaces "No upkeep/No schedule".)
- Remove the standalone "Pause upkeep/Resume upkeep" bar button and its overflow item. The drawer owns Pause/Resume.
- Optional chip, only when net granted: `Internet on` (globe icon), opens Permissions. Absent otherwise.

Responsive: >=900 px one row. 600–899: identity row, then actions row; History moves into ⋯. <600: Upkeep and History in ⋯; Refresh now and Permissions stay. Name `text-overflow: ellipsis`, one line; meta wraps to max two lines then clamps. All targets >=32 px high; ⋯ is 32x32.

## 2. Sandbox notice

Decision: remove the persistent caption row (`.ls-caption`). It repeats on every open, adds a 28 px strip, and states a boundary the frame already shows. Necessary restrictions stay discoverable and are raised when they matter.

1. Frame boundary: `.ls-sandbox` gets a 1 px `--ls-line` border, 12 px radius, 12 px inset from the bar. This replaces the caption visually.
2. First open per Space per device: one dismissible info Banner above the frame (localStorage key `ls.sandbox-note.{sid}`):
   - Title: `Made by {owner}, running in a sandbox`
   - Body: `It can't reach Hermes, your files or other Spaces, and it uses only what Permissions allows.`
   - Actions: `Review permissions` · `Got it`
   - Dismiss focuses the first focusable element in the frame bar. Role=status, not alert.
3. Always available: Permissions drawer top section "What this Space can't do" is not needed; the existing Internet access row and WebRTC text carry the rest.
4. When Internet access is on: show the header chip `Internet on` (see section 1). That is the only persistent sandbox-related signal, because it is the only state that changes risk.
5. Archived/crashed/building frames: no sandbox copy.
If product wants the first-open banner cut too, drop item 2; nothing else depends on it.

## 3. Upkeep panel (live view of the native cron job)

Surface: existing right Drawer, width min(460px,100vw), title `Upkeep · {Space}`. Source of truth: GET `{base}/upkeep` (job, link, executions, one_shots). Poll 5 s; 2 s while job is running or within 60 s of an action; pause polling when the document is hidden.

Order top to bottom (replace the Kind/Schedule/Cadence/Timezone/State rows):
1. Status row: pill `Active` | `Paused` | `Running now` (spinner) | `Job missing`.
2. Prompt (agent jobs): label `What Hermes does each run`; the prompt in a block, 13 px, pre-wrap, overflow-wrap anywhere, clamped to 6 lines with `Show full prompt` / `Show less` toggle (button, aria-expanded). Under it, 12 px secondary: `Uses model calls.` Feed jobs: `Refreshes from public sources. No model calls.` instead of a prompt.
3. Facts (dl, 110 px labels, existing grid):
   - `Runs`: `{schedule_display}` e.g. `Every day at 6:00 AM`; second line secondary `{timezone}`. If no schedule_display, show raw cadence.
   - `Next run`: active → `{absolute} · in {rel}`; paused → `Paused. It won't run until resumed.`; no next_run while active → `Waiting for Hermes to schedule it`.
   - `Last result`: never → `Hasn't run yet`; ok → `Succeeded · {absolute}`; failed → `Failed · {absolute}`; running → `Running now…`.
   - Under the facts, one 12 px secondary line: `If Hermes is asleep at run time, it runs once when it wakes. Missed runs aren't replayed.` (replaces the "If Hermes is asleep" section heading).
4. Actions row: `Run now` · `Pause`/`Resume` · (spacer) · `Remove` (ghost, danger text). Icons run / debug-pause / play. When paused, `Resume` is the primary button.
5. Action feedback line (role=status, aria-live=polite) directly under the actions.
6. `Executions` list (existing). `Refresh now runs` section (existing) stays last.

States — exact copy:
| State | Presentation |
|---|---|
| Loading | Skeleton: pill + three fact rows + button row, fixed heights, `aria-busy`. After 8 s add `Still waiting for Hermes…` (secondary). |
| Load error, no data | ErrorState title `Upkeep couldn't be loaded`, description `Hermes didn't respond. {error}` + `Try again`. |
| Refetch error, have data | Keep data. Banner failed: `Showing the last loaded state from {rel}.` + `Try again`. |
| Absent (no link) | Title `No upkeep yet`. Body `This Space isn't updated automatically. Ask {owner} in chat to set up upkeep as a Hermes cron job.` + CopyPrompt (existing text). No action buttons. |
| Active, healthy | As above. |
| Running | Pill `Running now`; `Run now` disabled with `title="Already running"` and aria-disabled; Pause stays enabled. |
| Paused | Pill `Paused`; Next run copy above; `Resume` primary; `Run now` still enabled. No banner. |
| Last run failed | Banner failed above facts: title `Last run failed {absolute}`, body = last_error clamped to 3 lines with `Show more`, actions `Run now` (retry) · `View history`. Next run still shown. |
| Job missing | Banner blocked: `Hermes no longer has this job` / `Nothing will run. Ask {owner} in chat to schedule upkeep again.` + `Remove link` + CopyPrompt (existing). |
| Archived | All actions disabled; line `Archived Spaces don't run upkeep. Restore the Space to use it.` |
| Cron unavailable | Banner failed `Hermes cron is unavailable` + data.error (existing). |

Action feedback:
- Run now: button `Starting…` (aria-busy, disabled). Success: `Run started. Hermes is working on it.` then Last result flips to Running now via fast poll. Failure: `Couldn't start the run. {error} Nothing changed.`
- Pause: success `Paused. Nothing will run until you resume.` Resume: `Resumed. Next run {absolute}.`
- Remove: existing confirm dialog. Title `Remove upkeep for {Space}?` Body `This deletes the Hermes cron job. The Space and its data are kept.` Buttons `Keep upkeep` (initial focus) / `Remove`. After success drawer shows Absent state with feedback `Upkeep removed. {Space} is unchanged.`; focus moves to the feedback line.
- Any failure: role=alert inline error under actions, then refetch so the UI shows server truth. Controls re-enable after request settles; busy uses `aria-disabled`, not `disabled`, so focus isn't dropped.
- Feedback lines clear after 8 s or on the next action.

A11y: facts `<dl>`; pill text, not colour alone; prompt toggle keyboard operable; focus order drawer: Close → Run now → Pause/Resume → Remove → toggles; focus returns to opener on close (existing). Forced-colors: pill keeps 1 px border. Reduced motion: no spinner rotation, show `Running now` text only.

## 4. Internet access switch row (Permissions drawer, top section)

Layout (one row, min-height 56 px):
`Internet access` (14 px/600) ........ `Off` text + switch (40x24 track, 18 px thumb), vertically centred. Description underneath, 12 px secondary, max 60ch, linked via aria-describedby.
Narrow (<360 px): switch and state text wrap beneath the title, left aligned.

Control: keep `<button role="switch">`, but render as a real switch (track + thumb), not a text button. `aria-labelledby` points to the visible title. State text `On`/`Off` is visible beside it (not colour-only). Track: on = accent fill, off = `--ui-stroke-secondary` fill plus 1 px border; thumb moves 16 px, 120 ms ease-out; none under prefers-reduced-motion. Forced-colors: track has `ButtonText` border; thumb uses `ButtonText`/`Canvas`.

Copy:
- On: `{Space} can load content from and send data to the internet. It still can't reach Hermes, your files or other Spaces.`
- Off: `{Space} can't load content from or send data to the internet.`
- Off, additional line (secondary, info icon, no box, no "Before you approve anything" title): `A browser feature called WebRTC can still send data this Space can read. It still can't reach Hermes, your credentials, your files or other Spaces.` Shown only while Off. Keep the existing wording of the disclosure; only the container changes.
- Requested (agent asked): switch Off and aria-disabled; description `{owner} is asking to turn this on.`; Approve (primary) / Deny buttons below. One decision surface, no duplicate control.
- Denied / revoked: switch Off and enabled; same Off description.
- Busy: aria-busy + aria-disabled, state text `Turning on…` / `Turning off…`, thumb dimmed.
- Success announce (live region): `Internet access turned on for {Space}.` / `…turned off for {Space}.`
- Failure (role=alert, under row): `Couldn't turn Internet access on. {error} It's still off.` (mirror for off). Switch shows server state.
- Turning on/off is immediate, no confirm: reversible, consequences stated inline. (Decision for product/Ife to veto.)

Keyboard/focus:
- Tab reaches the switch in DOM order after Close. Space and Enter toggle (native button). Focus stays on the switch through busy and result; never use `disabled` (it drops focus, current bug in source: `disabled={busy}`).
- Focus ring: existing 2 px accent, 2 px offset, must not clip inside the row.
- Hit area: whole 40x24 track plus 8 px padding = >=44x40. The title text is not clickable.
- Screen reader: "Internet access, switch, off. {description}".
