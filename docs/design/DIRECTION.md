# Living Spaces — host-surface design direction (v1, for release 1)

Owner: Miro. Status: **design direction, not implemented, not accepted.** Synthetic fixtures only (fictional Spaces, bots, times). Prototype: `prototype/index.html` (open in a browser; the top bar switches states and is not product UI). Screens: `screens/01…12-*.png` (1440×900 static frames, **not interaction evidence**).

Source of truth for behaviour: `docs/spec/SPEC.md` (v5.1). Visual language is replicated from Hermes Desktop `styles.css` dark theme and the Kanban plugin: `--ui-*` tokens, `--bg-card` surfaces, 12px/0.75rem radii, codicon-weight 1.6 stroke icons, accent `#0053fd`.

## Principles
1. **Native first.** Same sidebar row, page padding (28px), type (14px/1.5, title 20/600), cards (`--ui-bg-card`, 1px `--ui-stroke-2`), buttons (32px, 8px radius, accent primary). Use existing Hermes components (Button, Dialog/Sheet, Tabs, Tooltip) — do not hand-roll.
2. **Tile accents.** Each Space has a *tile*: 40px rounded square, 22% tint of its accent over chrome, 48% accent border, lightened accent glyph. Accent comes from the Space manifest (`accent`, `icon`), validated to a fixed 8-colour palette (blue #0053fd, green #55a583, amber #e0a06c, purple #9e94d5, teal #4c9fb0, rose #e75e78, orange #e08a64, grey #8a8a93). Hover tints the card 5% with the accent. **Accent is identity only, never status.**
3. **Status is never colour alone (R1-12).** Every status = icon + word + pill border style. Building = dashed border; Archived = dotted; Failed/Blocked also tint the card border. Save state is icon + text.
4. **No in-page editor or chat box.** Wherever a change is needed, show a *copyable chat prompt* (“Atlas, … please fix it”) and a Copy button.
5. **Freshness is three separate facts**: last successful update, last attempt, source freshness (spec §3). Never show one merged “updated” time when they differ.

## Status vocabulary (exact copy; icon in brackets)
| Status | Icon | Pill style | Card line 1 | Card line 2 |
|---|---|---|---|---|
| Ready | check-circle | solid, green text | Updated 12 min ago | Next refresh 3:00 PM |
| Building | hammer | **dashed** | `<Bot>` is building the first version | Started 2 min ago |
| Updating | refresh (spins; static if reduced motion) | solid, blue text | Refreshing now… | Last good update 8:00 AM |
| Failed | x-circle | solid, rose, tinted | Refresh failed 9:15 AM | Showing last good data from 6:15 AM |
| Blocked | no-entry | solid, amber, tinted | Refresh blocked 7:00 AM | Owner bot Kit is unavailable (names the cause) |
| Archived | archive | **dotted**, dim | Archived Oct 3 | Schedules stopped |
| Paused (upkeep) | pause | plain | — | — |
Crashed is a Space-frame condition (rose pill “Crashed”); in the index it renders as Failed with line 1 “Stopped working 9:21 AM”.

## 1 · Spaces index (`01-index`, `02-empty`)
- Page: title “Spaces” + summary `5 active · 2 need attention` (tabular numerals). Toolbar: search (34px, inset shadow, label “Search Spaces or owner”), segmented filter **All / Needs attention · n / Archived**, right-aligned “Sorted by recently used”. Pinned Spaces sort first (pin glyph + sr-only “Pinned”).
- Grid `repeat(auto-fill,minmax(300px,1fr))`, gap 12. Cards are one `<a>` (whole card is the target, Enter opens, visible 2px focus ring, `aria-label` = “Name, Status, owner Bot. freshness. next”). Content order: tile + name + owner chip (initial avatar in bot colour + name) → 2-line description → status pill → hairline → freshness lines.
- Attention (Failed/Blocked) cards get a 40% rose border; Archived at 78% opacity (still ≥4.5:1 text).
- Sidebar row **Spaces** shows a count badge `⚠ 2` (icon + number, aria-label “2 Spaces need attention”) only when attention > 0.
- **Empty state (first Space):** no illustration beyond three tile glyphs. Heading “Build your first Space in chat”, one sentence of what a Space is, two **copyable example prompts**, primary “Start a new chat”. Footnote: “New Spaces appear here, labelled Building until ready.”
- No-results: “No Spaces match “…”. Try another name or owner.” (role=status). Filter with nothing: “Nothing needs attention.”
- Footer hint (index only, one line): “Spaces are built and changed in a normal chat…”.

## 2 · Space view frame (`03-space`, `08-history`, `09-revisions`)
Frame bar (sticky, above sandboxed content): `‹ Spaces` crumb · tile(32) · **Name** + status pill · second line: owner chip · “Last successful update **9:15 AM** · source data from 9:10 AM”. Right cluster, in order: save indicator · schedule chip (“Daily 7:00 AM CT”, opens Schedule) · Pause/Resume upkeep · History · Permissions · **Refresh now** (only primary button). Wraps to a second row below ~1200px; below 900px secondary actions collapse into a “⋯” menu (keep Refresh now + Permissions visible).
- Sandbox region: bordered 12px-radius container labelled “Space content”; faint caption “Content below the bar is generated by this Space and runs sandboxed”. The host never draws inside it except the Crashed overlay.
- **Refresh now**: while running → label “Refreshing…”, icon spins, button stays focusable and `aria-busy`, repeat activation ignored (spec: no duplicate work). Result announced in the save/status live region: “Refresh succeeded: 2 new papers” / “Refresh failed”. Disabled (aria-disabled, with tooltip reason) when Blocked or Archived.
- **Save indicator** (`role=status aria-live=polite`): `Saving…` (spinner) → `Saved 9:16 AM` (check) → `Not saved — “Priority” change was not stored` (x, plus error banner with Retry save) → `Conflict — this record changed elsewhere` (triangle, plus banner: Keep my note / Use updated record / Compare). Never show Saved for volatile state.
- **Schedule drawer**: next run, last attempt, cost (“No model calls…”), if-asleep policy (“Runs one current refresh when Hermes wakes. Missed intervals aren't replayed.”). Changing a schedule = chat; button “Change schedule in chat” copies a prompt. Pause upkeep lives here and in the bar.
- **History & revisions drawer** (right sheet 460px, tabs): *Run history* rows = icon, outcome, trigger · time · duration, one line of result, status pill (Succeeded/Failed/Blocked; “no change” runs are shown truthfully). *Revisions* rows = number, time, author·summary, `Current` chip or **Restore…**. Restore confirm: “Restore revision 5? This brings back the Space's earlier code as a new revision 8. Revisions 6–7 stay in history. Your records, notes and statuses stay as they are now.” Buttons “Cancel” / “Restore as new revision”. Header note on the tab: restoring code does not rewind records (R1-10).
- Drawers: modal sheet with scrim, focus moves to Close, focus trap, Esc closes and returns focus to the invoking button.

## 3 · Permissions panel (`04-permissions`, `12-revoke-confirm`)
Right sheet “Permissions · <Space>”. Order:
1. **WebRTC note, always first, always visible without scrolling or expanding** (R1-05), exact spec §2 copy: “Spaces block ordinary internet connections unless you approve a site or capability. This is not a complete block: a browser feature called WebRTC can still send data that this Space can read. It does not give the Space access to Hermes, credentials, your unapproved files or other Spaces. Only put data in a Space that you trust it to handle.” Heading “Before you approve anything”. Do not rewrite or shorten.
2. **Granted to <Space>**: one card per grant: capability name · status pill (Allowed / Needs your decision / Denied / Revoked) · definition list **Scope · Purpose · Data leaves device · Access** (Continuing vs Once) · actions. Release 1 grants: Own data, Refresh, Diagnostics.
3. **Waiting for your decision**: pending grant (amber tint) with **Approve**, **Deny**, **Approve narrower…** (the narrower scope is chosen from host-defined options, never free text). Denied → “Denied. The Space shows “… isn't available” instead of prompting again.”
4. **Revoke** is danger-styled, opens an alertdialog: “Revoke Refresh for <Space>? Scheduled and manual refreshes stop and show Blocked. Data already delivered to the Space can't be recalled, and completed requests can't be undone.” Default focus on “Keep access”.
5. **Coming in release 2 — not available yet** (placeholders, *not working*): Approved sites, Camera, Microphone, Location, Hermes tools (per tool), Files and folders. Dashed outline, dim text, “Not available yet” chip, no buttons, no toggles. Footnote: “Camera, microphone and location will start off and also follow Hermes and macOS permission prompts. Release 2 will revisit what Spaces can read before tool and file access is offered.”
Also show owner + “Audit” entry (release 2: audit list) — release 1 shows only the three grants.

## 4 · Error and diagnostic states (`05–07`, `10–11`)
All use a full-width banner under the frame bar (`role=alert` for new failures, `role=status` for info). Banner = icon + **one-sentence headline stating what the user is seeing** + one line cause/safety + 1–2 actions. Banners are tinted, never colour-only.
- **Failed refresh with last-good data** (`05`): “Refresh failed at 9:15 AM. You're seeing data from 6:15 AM.” / “The source didn't respond (timeout after 30 s). Your notes and statuses are unchanged. Next automatic try 10:00 AM.” Actions: View run details, **Try again**. Content stays visible with saturation −30% (stale cue) — not hidden.
- **Blocked run** (`06`): “Refresh is blocked: the owner bot is unavailable.” / “Atlas isn't connected, so scheduled and manual refreshes can't run. The Space still opens and your data is safe. The last run (7:00 AM) never started.” Actions: Review permissions, **Reconnect Atlas**. Same pattern for revoked grant (“Refresh was revoked in Permissions”) and missing connection. Refresh now disabled with reason.
- **Crashed Space** (`07`): frame bar stays; sandbox area replaced by a centered card: “Research Desk stopped working” / “The Space hit an error and was stopped. Your records are safe and weren't changed by the crash.” Bounded diagnostic `<pre>` (error, location, revision, “logged to this Space only”, secrets redacted). Actions: **Reload Space**, **Restore revision 6…**; plus a copyable chat prompt “Atlas, Research Desk crashed in the Queue view. Please read its error log and fix it.” and line “Repairs happen in chat. Atlas can read this error and apply a new revision.”
- **Conflict** (`10`): see save indicator; user content is never lost; show both versions via Compare.
- **Archived** (`11`): info banner “This Space is archived. Refreshes and schedules are off.” / “Restore it to resume upkeep. Delete removes it and its data permanently.” Actions: **Restore Space**, Delete… (danger; confirm dialog must state data loss and that exported copies aren't recalled).
- **Building** (index card + frame): frame shows a skeleton sandbox with “Atlas is building the first version. This opens automatically when it's ready.” No actions except History.

## Accessibility checklist (what R1-12 will be checked against)
- Everything reachable by Tab in reading order; focus ring 2px `#7aa2ff`, 2px offset, on every interactive element; cards, pills-as-buttons, drawer controls.
- Drawers/dialogs: `role=dialog|alertdialog aria-modal`, labelled, focus into dialog, trap, Esc, focus return.
- Live regions: save indicator and refresh result (`polite`), new failures (`alert`). No toast-only information.
- Status = icon + text + border pattern. Text contrast ≥4.5:1 on `--bg-card`; dim text (`--text-3` #8a8a93) only for secondary info ≥12px and never for status or errors.
- Hit targets ≥28px (sm) / 32px (default). `prefers-reduced-motion`: spinner becomes static, no transitions.
- Times: absolute time with timezone on hover/`title` and in drawer; relative in cards.
- Tested here: static frames only, 1440×900 dark. **Not yet tested:** real keyboard walk in Desktop, screen reader, light theme, narrow widths <900, AX/large text, forced-colors. Light theme must derive from the same tokens (`--ui-*`), no hard-coded hexes beyond the 8-colour tile palette.
